## Bootstrap lessons

1. **No `sudo` on Runpod** — container is already root. `setup_env.sh` now no-ops sudo flags (`-E`, etc.).
2. **Ollama installer needs `zstd`.**
3. **`uv` lands in `~/.local/bin`** — new shells need `export PATH="$HOME/.local/bin:$PATH"`.
4. **Neo4j / Ollama installed natively** (Compose is unsupported inside pods).
5. **Rebuild the UI after pull** — `git pull` alone does not refresh `workbench-ui/dist`. Run `make workbench-ui` or the browser keeps the old JS hash.
6. **PDF upload through the Runpod HTTP proxy** — multipart POSTs never reached uvicorn. Fixed by posting raw `application/pdf` + `X-Filename`.

## OCR: what failed, then what worked

### Failures (in order)

| Attempt | Symptom | Root cause |
| --- | --- | --- |
| Surya auto backend | `SpawnError: docker binary not found` | NVIDIA present → Surya picks **vLLM/Docker**; Runpod cannot nest Docker |
| ggml-org CUDA tarball (`b11946` ubuntu-cuda-12.8) | `GLIBC_2.38 not found` | Release needs newer glibc than Ubuntu 22.04 |
| `llama.app` CLI (`~/.local/bin/llama`) | `error: unknown command '-m'` | Different CLI than classic `llama-server`; rejects Surya’s spawn flags |
| Ollama `llama-server` without CUDA env | `no usable GPU found`, VRAM stuck ~500 MiB, CPU-only | Binary exists but CUDA backend `.so` not loaded |

While stuck, Runpod UI often showed **100% GPU util / ~500 MiB VRAM** — that footprint appeared even during bootstrap idle and is **not** proof the OCR model is resident.

### Working configuration

```bash
export PATH="$HOME/.local/bin:/usr/local/bin:$PATH"
export LLAMA_CPP_BINARY=/usr/local/lib/ollama/llama-server
export LD_LIBRARY_PATH=/usr/local/lib/ollama/cuda_v13:/usr/local/lib/ollama:${LD_LIBRARY_PATH:-}
export GGML_BACKEND_PATH=/usr/local/lib/ollama/cuda_v13/libggml-cuda.so
export SURYA_INFERENCE_PARALLEL=2
export SURYA_INFERENCE_CTX_SIZE=24576
# optional for long pages:
# export SURYA_INFERENCE_TIMEOUT_SECONDS=1800
# export SURYA_INFERENCE_KEEP_ALIVE=1

# Verify GPU is visible to llama-server before OCR:
llama-server --list-devices
# expect: CUDA0: NVIDIA GeForce RTX 5080 (... MiB)
```

Sanity check once OCR is running:

```text
nvidia-smi
# llama-server process with ~2–3 GiB VRAM, util high
```

### Measured OCR result (this session)

- Input: 2 atomic pages from UCSF pulmonary lab fax (`ucsf_nlgb0106_..._page_001/002.pdf`)
- Backend: Surya GGUF via Ollama’s classic `llama-server` + `cuda_v13`
- Throughput while generating: ~**17–20 tok/s**
- Wall time for the batch: ~**661 s** (~11 min) including model load
- Output:
  - `page_001.json` — 16 blocks (Text, SectionHeader, Table, PageFooter, …)
  - `page_002.json` — 11 blocks
- Client wait timer approached the default **600s** timeout; batch still completed (~660s). Prefer `SURYA_INFERENCE_TIMEOUT_SECONDS=1800` for dense pages.
